City Care Hospital — Token & Appointments

Complete single-hospital Flutter app: book doctors from home, auto-issue tokens (T-01…), and track the live queue so patients arrive just in time.

Default backend: Local (no Firebase required)
Run locally Backend modes Roles Demo flows Queue logic Data model Project structure Screens Optional Firebase Testing Future

1. Run the complete project (Local mode)

You do not need Firebase to run a full working demo. Local mode uses an in-memory hospital backend (MockDataStore) with auth, booking, tokens, live queue, receptionist, doctor, and admin screens. 
cd D:\GitHub\flutter2
flutter pub get
flutter run

Requires Flutter SDK on PATH. Android emulator or device recommended.

Demo login

  1. Finish / skip onboarding
  2. Pick Demo role: patient / receptionist / doctor / admin
  3. Phone: 03001234567 → Send OTP
  4. OTP: 123456 (any 4+ digits works in Local mode)

5. Token & queue logic

  • Separate sequence per doctor + calendar day; resets at midnight
  • Labels: T-01, T-02, …
  • Statuses: BOOKED → CHECKED_IN → IN_PROGRESS → COMPLETED | CANCELLED | NO_SHOW | SKIPPED
  • Patients ahead = lower token numbers still BOOKED/CHECKED_IN
  • ETA = patients ahead × average consult minutes
  • Grace no-show default: 10 minutes after call
  • “Turn near” alert threshold: 3 patients ahead
  • Cancel/reschedule cutoff: 2 hours
  • Max bookings per phone per day: 3
  • No double booking: same patient + same doctor + same day

9. Optional: switch to Firebase later

Only when you need real OTP SMS, multi-device sync, and push notifications:

  1. Create Firebase project hospital-token-app
  2. flutterfire configure
  3. Set useMockData = false
  4. cd functions && npm install && npm run build
  5. firebase deploy

Cloud Functions included: allocateToken, callNext, status updates, grace no-show, reminders, reports.

Markdown deep-dives (optional): see docs/01…docs/10 and DOCUMENTATION.md.
